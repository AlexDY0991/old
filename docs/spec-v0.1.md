> 给 Claude Code：这是一个 Demo 项目的完整需求。请按第 11 节的里程碑顺序推进，每个里程碑完成后停下来让我验收再继续。遇到第 12 节"待确认问题"里的事项，先问我，不要自行假设。第三方 API（语音模型、AlarmKit）更新很快，**实现前请先查阅官方最新文档**，不要凭记忆写接口。

---

## 1. 背景与目标

**一句话**：老人手机上的 app 每天定时像"来电"一样响起，老人点接听后和 AI「小暖」聊 3 分钟（睡眠、身体、心情、今天安排），聊完自动生成总结推给子女；如果老人没接，子女也会知道。

**Demo 的唯一目的**：用最低成本，在 5–10 个真实家庭里测出两个数字——
- 老人的**接听率**（以及第二周留存）
- 子女的**日报打开率**

凡是不影响这两个数字的功能，一律不做。

**参考产品**：海外的 Kin-nect、Joy Calls、Meela（它们用真实电话外呼；我们用 app 闹钟模拟来电，避开国内外呼资质和骚扰标记问题）。

---

## 2. 范围

### 做
- iOS 老人端 app（仅 iOS 26+，基于 AlarmKit）
- 后端服务：配置、语音中转、对话记录、总结、未接检测、通知
- 语音服务抽象层，同时接入两家实时语音模型做 A/B
- 子女端：H5 日报页（微信内打开）
- 管理员（我）通知：未接 / 高风险时推送给我

### 不做（Demo 阶段明确排除）
- 安卓、鸿蒙
- 微信服务号、小程序、短信
- 登录注册、付费
- 多子女复杂权限（Demo 里一个家庭的日报链接可以发给多个子女，但不做账号体系）
- 专门的吃药提醒功能（只在对话里顺带问）
- 设置页（老人端不提供任何设置项）

## 4. 核心流程

### 4.1 每日正常流程
1. 到达设定时间 T（如 09:00，Asia/Shanghai），AlarmKit 闹钟响起，标题「小暖来电」。
2. 老人点开 → 进入 app 的**仿来电页**（小暖头像 + 名字 + 大绿色"接听"按钮）。
3. 点接听 → 建立语音会话，小暖先开口问候。
4. 对话约 3 分钟，小暖主动道别结束（老人也可随时按大红色"挂断"）。
5. 会话结束 → 后端生成结构化总结 + 风险等级 → 更新当天 H5 日报。
6. 如果风险等级为"告警"，立即通知管理员。
7. 会话成功完成后，app 取消当天的备用闹钟（见 4.2）。

### 4.2 未接流程（关键：由后端判断，不依赖 app 上报）
- app 每天设两个闹钟：主闹钟 T、备用闹钟 T+10 分钟。
- 主闹钟被划掉/没理会 → 备用闹钟再响一次。
- 会话成功完成后，app 取消当天的备用闹钟。
- **后端**在 T+30 分钟检查：当天没有"已完成"的会话 → 记为"未接"，通知管理员，并在日报上标记"今天还没聊"。
- 注意：AlarmKit 无法检测用户划掉闹钟，所以"没聊"只能靠后端超时判断，这是设计上的必然，不要试图在客户端检测。

### 4.3 通话中断
- 网络断开 / app 崩溃：已产生的对话记录要保留（因为对话经过后端中转，后端天然有记录），会话标记为"部分完成"，照常生成总结。
- 连接失败：app 显示大字"网络不太好，小暖等会儿再打来"，并上报失败事件（如果能上报的话）。

## 5. 系统架构

```
┌────────────────┐   WSS(音频)   ┌──────────────────────┐   WSS   ┌──────────────────────┐
│ iOS 老人端 app  │ ───────────▶ │ 后端（语音中转 + 业务） │ ──────▶ │ 实时语音模型          │
│ AlarmKit 闹钟   │ ◀─────────── │ FastAPI + SQLite      │ ◀────── │ 智谱 GLM-Realtime    │
│ 仿来电 UI       │              │ 调度器 / 总结 / 通知    │         │ 阿里 Qwen-Omni-RT    │
└────────────────┘              └──────────┬───────────┘         └──────────────────────┘
                                           │
                     ┌─────────────────────┼─────────────────────┐
                     ▼                     ▼                     ▼
              H5 日报页（子女）       文本大模型（总结）      管理员通知（Server酱/邮件）
```

**原则**
- **API Key 只在后端**，绝不写进 iOS app。app 只连我们自己的后端。
- 对话发生在服务器侧：后端把 app 的音频转发给语音模型，同时拿到双方转写文本并落库。
- 语音模型通过抽象层接入，换供应商只改配置。

**技术栈建议**（可在 M1 前跟我确认）
- iOS：Swift + SwiftUI，最低 iOS 26
- 后端：Python 3.11+、FastAPI、SQLite（Demo 足够）、APScheduler、Jinja2（H5 模板）
- 部署：需要公网 HTTPS + WSS（见第 12 节待确认）

## 6. 模块需求

### 6.1 iOS 老人端

**页面（只有这几个）**
1. **首次绑定页**：大字提示 + 输入 6 位绑定码（管理员生成；可通过视频通话远程指导输入）。绑定成功后永不再出现。
2. **知情同意页**（首次绑定后显示一次）：大字 + 小暖语音朗读，说明"我是 AI 小暖，每天会给您打电话聊聊天，聊天内容会整理后发给您的家人"。一个大按钮"好的，我知道了"。
3. **待机页**：显示"小暖每天 9:00 给您打电话"+ 小暖头像。没有任何其他操作入口（可以有一个隐藏的长按调试入口给我用）。
4. **仿来电页**：全屏，小暖头像、名字、"小暖来电…"、大绿色接听按钮。
5. **通话中页**：小暖头像 + 简单的说话波形/动画 + 大红色挂断按钮。显示通话时长。
6. **结束页**：大字"今天聊得真开心，明天见！"，3 秒后回到待机页。

**适老化硬性要求**
- 主文字 ≥ 28pt，按钮高度 ≥ 88pt，高对比度，不使用细字重
- 一个页面只有一个主要动作
- 不出现任何英文、图标含义不明的按钮、弹窗确认链
- 系统权限请求（麦克风、闹钟）在绑定时由子女/我协助完成，引导文案要清楚

**闹钟（AlarmKit）**
- 绑定后从后端拉取问候时间，用 AlarmKit 设置每日重复的主闹钟 T 和备用闹钟 T+10
- 闹钟点开后直接进入仿来电页
- 会话完成后取消当天备用闹钟（注意：需要确认 AlarmKit 对"取消重复闹钟中的某一次"的支持方式；如不支持，可改为每天动态设置次日的两个单次闹钟）
- 每次 app 打开时校验闹钟是否仍在，不在则重建
- 可参考我已有项目 TataAlarm（獭獭闹钟）中的 AlarmKit 实现

**音频**
- AVAudioSession：playAndRecord，开启语音处理（回声消除、降噪），默认外放（老人习惯外放）
- 音频格式按后端约定（建议 PCM16、16kHz、单声道；以所选语音模型官方文档为准）
- 支持打断：老人说话时小暖应停止播放

**与后端通信**
- `GET /api/elder/config`：拉取问候时间、小暖名字/头像、称呼
- `WSS /ws/call`：通话音频双向流
- `POST /api/elder/events`：上报事件（app_opened_from_alarm、call_started、call_ended、call_failed）
- 鉴权：绑定后获得 elder_token，存 Keychain

### 6.2 后端

**API 列表**

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/families` | 创建家庭（老人档案、问候时间、语音供应商），返回 6 位绑定码和日报链接 |
| GET | `/api/admin/families` | 列出所有家庭及今日状态 |
| POST | `/api/elder/bind` | 用绑定码换 elder_token |
| GET | `/api/elder/config` | 老人端配置 |
| POST | `/api/elder/events` | 客户端事件上报 |
| WSS | `/ws/call` | 通话中转（鉴权 elder_token） |
| GET | `/r/{report_token}` | H5 日报（今天） |
| GET | `/r/{report_token}/{date}` | H5 日报（指定日期） |

管理接口用一个固定的 admin key 鉴权即可；可以再配一个命令行脚本 `manage.py create-family` 方便我操作。

**调度器**
- 每分钟运行：找出"问候时间 + 30 分钟已过、当天无完成会话、尚未标记"的家庭 → 标记未接 → 通知管理员
- 每晚 21:00：给管理员发一条当日汇总（各家庭：是否聊了、时长、风险等级、日报是否被打开）

**通话中转（/ws/call）**
1. 鉴权 → 读取老人档案 + 最近 3 天的总结
2. 按 6.4 节组装 system prompt
3. 通过语音抽象层连接所选供应商，双向转发音频
4. 实时保存双方转写文本（role、text、timestamp）
5. 会话结束（任一方挂断、超时 8 分钟强制结束、连接断开）→ 写入会话状态 → 异步触发总结

### 6.3 语音服务抽象层

```python
class VoiceProvider(Protocol):
    async def connect(self, system_prompt: str, voice: str) -> None: ...
    async def send_audio(self, pcm_chunk: bytes) -> None: ...
    def events(self) -> AsyncIterator[VoiceEvent]: ...  # audio_out / user_transcript / ai_transcript / turn_end / error
    async def close(self) -> None: ...
```

**首批实现两个**
- `GLMRealtimeProvider`：智谱 GLM-Realtime（glm-realtime-air / flash，目前限时免费；注意其上下文记忆约 2 分钟）
- `QwenOmniRealtimeProvider`：阿里百炼 qwen3-omni-flash-realtime（支持上海话、粤语、四川话等方言，是老人场景的重点测试对象）

**要求**
- 每个家庭可配置使用哪家（便于 A/B）
- 统一内部音频格式，供应商差异在各自实现里转换
- 连接失败时自动重试 1 次，仍失败则 app 端显示"等会儿再打来"
- 记录每次会话的供应商、首字延迟、总时长，方便比较
- M1 阶段先写一个**命令行测试脚本**：用 Mac 麦克风直接和两家模型对话，验证延迟和效果，再接 app

### 6.4 对话设计（小暖人设 prompt 草稿）

> 以下为初稿，实现时放在独立的模板文件 `prompts/xiaonuan_system.md` 里，方便我反复修改，不要硬编码。

```
你是「小暖」，一个每天给老人打电话问候的 AI。你正在和{elder_call_name}通电话。

【身份】
- 你是 AI，开场第一句就要自然说明："{elder_call_name}早上好，我是小暖，是您家人给您安排的 AI 小助手，每天来陪您聊几句。"（之后的通话可简化为"我是小暖"）
- 如果对方问你是不是真人，诚实回答你是 AI。

【说话方式】
- 语速慢，句子短，一次只问一个问题。
- 口语化、温暖，像邻居家懂事的晚辈，不要像客服或医生。
- 顺着老人的话聊，不纠正、不说教、不讲大道理。
- 老人没听清时，换个更简单的说法重复。

【这通电话要自然聊到的（按顺序，但不要像问卷）】
1. 问候 + 昨晚睡得怎么样
2. 身体有没有哪里不舒服（如果说有，追问一句具体情况）
3. 今天打算做什么 / 吃了没有
4. 聊一件开心的事（可以从老人的兴趣切入：{interests}）
5. 提醒一件事（天气：{weather_hint}；如有用药：{medication_hint}）
6. 温暖道别："那今天就聊到这儿，明天这个时候小暖再给您打电话。"

【参考信息】
- 老人基本情况：{elder_profile}
- 最近几天聊过的内容（可以自然地接上话题，比如"您昨天说膝盖疼，今天好点没？"）：{recent_summaries}

【时长】
- 控制在 3 分钟左右。老人聊得开心可以延长，但不超过 6 分钟。

【安全规则 —— 最高优先级】
- 如果老人提到摔倒、胸口疼、喘不上气、头晕得厉害、说话不清、想不开等紧急情况：
  立刻停止闲聊，平静清楚地说："这个情况很重要，请您马上给家里人打电话，或者拨打 120。"重复一次。
- 不给任何医疗诊断、用药建议。身体问题一律建议"跟孩子说一声，或者去医院看看"。
- 不推销、不提任何商品或服务。
- 不承诺你做不到的事（比如"我会帮您叫救护车"）。
```

### 6.5 总结与风险判断

会话结束后，用一个文本大模型（便宜的即可，可配置）把转写文本整理为以下 JSON，**必须基于转写原文，不得编造**：

```json
{
  "completed": true,
  "duration_sec": 186,
  "mood": "好 | 一般 | 低落 | 无法判断",
  "sleep": "一句话，无则为 null",
  "physical_complaints": [
    { "summary": "右膝盖疼", "quote": "膝盖有点疼，昨天没下楼" }
  ],
  "medication": "吃了 | 没吃 | 未提及",
  "today_plan": "一句话，无则为 null",
  "needs": ["想让孩子周末回来"],
  "highlights": "一句话，今天聊到的开心事",
  "risk_level": "normal | attention | alert",
  "risk_reasons": ["提到头晕"],
  "one_line_for_family": "妈妈今天精神不错，就是膝盖还有点疼。"
}
```

**风险判断两层，取更高者**
1. **规则层**（转写文本命中即至少 `alert`）：摔、跌倒、胸口疼、胸闷、喘不上气、呼吸困难、头晕、说不出话、手脚麻、晕倒、出血、想死、不想活、活着没意思 等（关键词表放配置文件）
2. **模型层**：综合判断情绪低落、反复说同一件事、明显糊涂、与前几天相比明显异常 → `attention` 或 `alert`

**原则：宁可误报，不可漏报。** `alert` 立即通知管理员。

### 6.6 子女端 H5 日报页

- 服务端渲染（Jinja2），移动端优先，在微信内置浏览器里打开体验良好
- 无登录，靠 `report_token` 访问（链接不可猜测）
- 页面内容：
  1. 顶部状态卡：今天聊了 ✅ / 今天还没聊 ⚠️ / 需要注意 🔴，以及 `one_line_for_family`
  2. 今日详情：心情、睡眠、身体情况（附老人原话）、用药、今天安排、需求、开心事
  3. 最近 7 天：每天一个小圆点（颜色表示状态）+ 心情趋势
  4. 底部小字：「小暖是 AI，不是急救服务。如遇紧急情况请直接联系老人或拨打 120。」
- 记录每次打开（时间、日期参数），用于统计打开率

### 6.7 管理员通知

- 通知通道做成可插拔：先实现 Server酱（推送到我的微信）和 SMTP 邮件两种，配置里选
- 触发：未接、`alert`、每晚 21:00 汇总
- 通知内容包含家庭名、事件、日报链接

## 7. 数据模型（SQLite）

- **families**：id、name、voice_provider、call_time（HH:MM）、timezone（默认 Asia/Shanghai）、bind_code、report_token、created_at
- **elders**：id、family_id、call_name（称呼，如"王阿姨"）、profile（文本：年龄、居住情况、健康关注点）、interests、medication_hint、elder_token、consent_at、bound_at
- **call_sessions**：id、family_id、date、provider、status（completed / partial / failed / missed）、started_at、ended_at、duration_sec、first_response_ms
- **transcript_turns**：id、session_id、role（elder / ai）、text、ts
- **summaries**：id、session_id、json、risk_level、created_at
- **events**：id、family_id、type、payload、ts（客户端事件 + 日报打开记录）
- **alerts**：id、family_id、session_id、type（missed / alert）、notified_at

## 8. 隐私与合规（Demo 也必须做）

- 老人本人在 app 内完成知情同意（第 6.1 节第 2 页），记录 `consent_at`
- 每次通话开头 AI 声明身份
- **默认不保存录音**，只保存转写文本和总结
- 所有 API Key 只在服务器环境变量中
- 提供一个管理命令：按家庭彻底删除全部数据
- 数据存储在国内或香港服务器（见第 12 节）

## 9. 指标与统计

后端提供一个管理接口/脚本输出以下统计（按家庭、按天）：
- 接听率 = 完成会话天数 / 应问候天数
- 平均通话时长、首字延迟（按供应商分组）
- 第 2 周接听率 vs 第 1 周
- 日报打开率 = 有打开记录的天数 / 有日报的天数
- 告警次数

## 10. 非功能要求

- 关键路径要有日志（会话建立、供应商错误、总结失败、通知失败）
- 所有可调参数（关键词表、超时时间、prompt 模板、通知通道）放配置文件
